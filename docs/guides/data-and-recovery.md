# データ・移行・復旧

[简体中文](../zh-CN/guides/data-and-recovery.md) · [English](../en/guides/data-and-recovery.md) · 日本語

[ドキュメント一覧](../README.md)

## 保存先と保管

管理情報は `~/.ssh/ssh-keyflow/state.json`、生成鍵は同ディレクトリの `keys/` に保存します。取り込みは明示したファイルを参照し、元ファイルは移動・書き換えません。公開鍵の指紋と秘密鍵ファイルのダイジェストを検証し、不一致や読み取り不能は要確認として止めます。秘密鍵の内容やパスフレーズは状態JSON・引数へ保存しません。

更新や移行前にはアプリを終了し、`~/.ssh/ssh-keyflow/` をアクセス制限された別の場所へ保管してください。状態JSONだけでは秘密鍵を復元できません。取り込んだ鍵の元ファイルと、自分で設定したSSH configも必要に応じて別途保管します。秘密鍵を含む控えは公開リポジトリや共有ログへ置かないでください。

復元前にも現在のデータを退避し、使用する版が保管済み状態を読めるか確認します。復元先のパスと鍵の指紋が一致することを確認してください。アプリに自動復元・状態の結合はありません。

## 中断と直前状態

鍵作成はネイティブの `ssh-keygen` を使い、既存パスを上書きしません。作成が中断した場合は `keys list` の作成IDで `resume` してください。保存済みのパス・指紋・ダイジェストとファイルを照合し、部分ファイルを自動削除せず再開します。未完了の作成がある間は別の鍵ペアを新規作成しません。状態変更は排他ロックで保護し、検証済みの直前状態を `state.json.bak` に保存してから原子的に置き換えます。不明なロックや不正な状態は自動修復しません。

## v0.10.0以前からの移行

v0.11.0は鍵ペアの管理だけに絞った意図的な非互換変更です。接続先・関連付け・手動設定ガイド・ホスト鍵の固定・TUI・公開鍵のみの取り込みを廃止しました。

v0.10.0以前の `state.json`（スキーマv1 / v2）は、読み取るだけでは変更しません。`keys list` は、次の変更で何を引き継がないかを標準エラーに表示します。変更操作も、確認を求める前に同じ内容を表示します。未知のフィールドや壊れた値を含む旧ファイルは読み込まず、何も変更しません。最初の変更操作（作成・取り込み・削除・再開）で、アプリは次の順に処理します。

1. 元の `state.json` をそのまま `~/.ssh/ssh-keyflow/state.v<N>-<UTC時刻>.json` へ書き出します。既存のファイルは上書きしません。書き出しに失敗した場合は何も変更しません。途中で失敗した操作をやり直したときは、同じ内容のアーカイブを再利用します。
2. 秘密鍵パスを持つ鍵と未完了の鍵作成だけを引き継ぎ、スキーマv3で保存します。

引き継がないものは、接続先と関連付け、削除済みレコード、旧登録・設定・SSH config編集・オンボーディング・削除の記録と履歴、公開鍵のみの鍵、未完了の旧鍵削除がある鍵です。これらはアーカイブに残ります。未完了のSSH config編集が表示された場合は、そのファイルを手動で確認してください。公開鍵のみの鍵が必要な場合は、対応する秘密鍵と組にして `keys import` で取り込み直してください。

旧版が作った `~/.ssh/ssh-keyflow/known_hosts`（ホスト鍵の固定ファイル）、`~/.ssh/ssh-keyflow/config`、通常の `~/.ssh/config`、Include、ガイドから追記したHostブロックは変更しません。固定用の `HostKeyAlias`・`UserKnownHostsFile`・`StrictHostKeyChecking` 行は、ファイルを残す限り引き続き機能します。不要なら自分で削除してください。

## 旧版へ戻す

旧版はスキーマv3を読めません。旧版へ戻す場合は、アプリを終了してから次を行います。

1. 現在の `~/.ssh/ssh-keyflow/` を別の場所へ保管します。
2. `state.v<N>-<UTC時刻>.json` を `state.json` という名前で戻します。

移行後に作成・取り込みした鍵は、戻した状態に含まれません。必要なら旧版で取り込み直してください。`state.json.bak` は直前状態の更新式バックアップで、移行後はv3になるため、旧版へ戻す用途には使えません。

過去の検証結果は [検証記録](../verification.md)、現在の仕様は [アプリケーション契約](../application-contract.md) を参照してください。
