# トラブルシューティング

[简体中文](../zh-CN/guides/troubleshooting.md) · [English](../en/guides/troubleshooting.md) · 日本語

[ドキュメント一覧](../README.md)

## コマンドが見つからない

新しい端末を開いて再試行します。PATH追加を断った場合は、インストーラーが表示した本体のフルパスを使ってください。Windows PowerShellとPowerShell 7ではプロファイルが異なります。[配置先とPATHの説明](installation.md)を参照してください。

## 変更操作が拒否される

作成・取り込み・削除・再開は実端末での確認を要求します。パイプへ流した `yes` で確認を代替せず、対話端末で実行してください。一覧と公開鍵の表示はリダイレクトできます。

## `unknown command "hosts"` などと表示される

`hosts`・`tui`・`--public-only` はv0.11.0で廃止しました。[CLIの使い方](cli.md#廃止したコマンド)と[移行の説明](data-and-recovery.md#v0100以前からの移行)を参照してください。

## 公開鍵をコピーしたい

次の出力をクリップボードやエディターへ取り込みます。名前は自分の管理名または固定IDへ置き換えます。

```sh
ssh-keyflow keys public --key laptop
```

公開鍵は1行を維持し、表示上の折り返しを改行として貼り付けないでください。

## 鍵作成が中断した

```sh
ssh-keyflow keys list
ssh-keyflow resume --id creation-example
```

`creation-example` は一覧の未完了作成IDへ置き換えます。再開は同じID・保存パスを使います。部分ファイルを削除して作り直したり、別の鍵を同じ場所へ上書きしたりせず、指紋・ファイルの不一致があれば内容を確認してください。

## 鍵・状態・ロックのエラーが出る

対象ファイルの移動・置換、権限、別プロセスの実行を確認します。アプリは不明なロックや不正な状態を自動修復しません。別の操作が進行中なら終了を待ちます。ロックや状態を無条件に削除せず、アプリを止めて[データと復旧](data-and-recovery.md)を確認してください。

## `state.json uses schema v1` / `v2` と表示される

旧版の状態です。次の変更操作で元のファイルをアーカイブし、鍵ペアだけを引き継ぎます。表示された「Not carried over」の内容を確認してから操作してください。詳細は[移行の説明](data-and-recovery.md#v0100以前からの移行)にあります。

## 公開鍵を配置してもSSH接続できない

SSH KeyFlowは接続を検証しません。接続先のSSHサーバー、ネットワーク、ログインユーザー、実際の `AuthorizedKeysFile` / `Match`、`authorized_keys` とその親ディレクトリの権限、ローカルのSSH configの `IdentityFile` を確認してください。Windowsの管理者アカウントでは `%ProgramData%\ssh\administrators_authorized_keys` が使われます。

パスフレーズを繰り返し要求される場合は、OSのssh-agentに鍵を読み込みます（`ssh-add <秘密鍵パス>`）。agentが終了すると読み込んだ鍵は保持されません。

## インストーラーが更新・削除を拒否する

所有記録のない既存ファイルや、配置後に変更されたファイルは上書きしません。バイナリを手動で差し替えた場合も所有ハッシュが一致しなくなります。[旧インストーラーと手動保守](installation.md#v010のインストーラー利用者)を確認し、他のファイルやプロファイル全体を削除しないでください。

## 報告に含める情報

[コントリビューション](../../CONTRIBUTING.md)の報告手順に従い、版、OS / CPU、端末、実行コマンド、期待結果、実際の診断、最小の再現手順を記録します。秘密鍵・パスフレーズ・認証トークンは含めず、ホスト名・ユーザー名・パス・状態の内容も公開前に確認してください。
