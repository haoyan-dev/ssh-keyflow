# ADR 0007: 鍵ペアの管理だけを残し、接続先・ガイド・TUIを廃止する

- 状態: 採用（v0.11.0）。範囲、`authorized_keys` の手動配置、known_hosts・SSH configを編集しない方針の更新をADR 0008で提案
- 日付: 2026-11-28
- 仕様: `.scratch/retire-non-essential/spec.md`
- 更新・廃止: ADR 0001（コピペ支援）、0002、0003、0004（履歴保持と接続先・関連付けの削除）、0005、0006

## 背景

利用者は多数のPC・VM・VPSを使い、新しい環境ごとのSSH設定を繰り返している。
求めているのは、新しい環境ではツールを取得するだけで、鍵ペアが環境間で
揃う仕組みである。インターネットを通すのは公開鍵だけで、ツールはローカルの鍵を
管理する。この方向の設計は後続の作業として別に検討し、決定時に別のADRで記録する。

v0.10.0までの機能のうち、接続先の記録、関連付け、コピペ用の手動設定ガイド
（ssh-agentステップを含む）、ホスト鍵の固定、端末UIは、1台ずつの手作業を
支援するためのものだった。新しい設計ではこれらを別の仕組みで置き換えるため、
保守し続けると状態スキーマ・テスト・3言語の文書の負担が残り、移行も難しくなる。

## 決定

ツールをこの端末の鍵ペアの管理に絞ったCLIにする。

- 残す：`keys list` / `keys public` / `keys create` / `keys import`（鍵ペアのみ）/
  `keys remove`、`resume`、インストーラーとPortable配布。
- 廃止：`hosts` の全サブコマンド（add / list / remove / associate / dissociate /
  guide / pin / unpin）、`tui` と引数なし起動のTUI、`keys import` の公開鍵のみ
  取り込み。指定すると使用法エラーにする。
- 状態はスキーマv3とし、`keys` と `creations` だけを持つ。完了した作成と
  削除した鍵のレコードは保持しない。

v1 / v2の状態は読み込み時に変換する。最初の保存の前に元のファイルを
`state.v<N>-<UTC時刻>.json` へ排他的に書き出し、引き継がない記録も失わない。
変換で残すのは秘密鍵パスを持つ鍵と未完了の作成だけで、接続先・関連付け・
削除済みレコード・旧履歴・公開鍵のみの鍵・未完了の旧削除がある鍵は落とす。
読み込みだけではファイルを変更せず、`keys list` と各変更コマンドの確認前に
落とす項目を種類ごとに予告する。旧スキーマの読み込みも厳格に保ち、未知の
フィールドや型の誤りを拒否する。再試行では同一内容のアーカイブを再利用する。

既存の `~/.ssh/ssh-keyflow/known_hosts`、SSH config、Includeは
引き続き編集しない。ガイドから利用者が追記した行は、ファイルが残る限り機能する。

## 検討した代案

- **旧スキーマを保ったまま新機能を隠す**：互換性は保てるが、使わない
  レコードの検証・移行規則が残り、次の設計の移行を難しくする。
- **TUIを鍵管理だけに縮小する**：依存17モジュールと端末ごとの検証が残る。
  新しい環境での作業は1行インストールとCLIで足りる。
- **公開鍵のみの鍵を残す**：エージェント・FIDO鍵向けの用途は、ガイドの
  `IdentityFile` 生成と組で意味があった。ガイドを廃止すると価値がなくなる。

## 影響

0.x開発での非互換変更のため、v0.11.0へMINORを更新する。v0.10.0以前の
バイナリはv3を読めず、ダウングレードには移行アーカイブを手動で戻す必要がある。
配布物の依存は5モジュールになり、`THIRD_PARTY_NOTICES.txt` を縮小した。
公開鍵の配置とSSH configの設定は、次の設計が入るまで利用者の手作業になる。
