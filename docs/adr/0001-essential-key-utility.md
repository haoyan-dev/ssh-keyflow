# ADR 0001: ローカル鍵管理とコピペ支援に機能を絞る

- 状態: 採用（v0.5.0）
- 日付: 2026-11-08
- 仕様: `.scratch/essential-key-utility/spec.md`

## 背景

従来は鍵作成・取り込みに加え、自動登録・解除、SSH接続確認、SSH設定とIncludeの編集、鍵削除と各処理の再開を担っていた。コピペで公開鍵を配置する用途にも、認証方式・リモート環境判定・設定所有権・復旧状態の選択と維持が必要になっていた。

利用者は必須機能への集約を求め、公開鍵の配置はコピペだけにする方針と推奨範囲の実装を承認した。この決定は `.scratch/ssh-onboarding/` の自動登録・解除・設定編集要件を置き換える。過去の仕様や検証記録は履歴として残し、現行契約として再利用しない。

## 決定

Ed25519作成、公開鍵のみを含む明示的な取り込み、鍵ペア検証、ローカル作成の中断再開を残す。Keys / DestinationsのTUIと薄いCLIから既存鍵と接続先を関連付け、公開鍵とOS・アカウント別配置先、手動解除案内、SSH Hostスニペット、POSIXシェル / PowerShellの接続コマンドを表示・コピーする。公開鍵のみなら秘密鍵を要するスニペット・コマンドを生成しない。

リモート登録・解除・接続確認、ブートストラップ認証、サーバー設定用スクリプト、SSH config / Includeの所有・編集、ローカル鍵削除、旧番号メニュー、Tasks、再帰的設定探索を外す。接続先追加では既存鍵を選び、新規鍵は独立して作成する。既存HostやIncludeとの重複・優先順位は利用者が確認する。

関連付けは登録履歴から独立したメタデータとする。コピーや保存で登録・接続成功を記録せず、手動成功の追跡も追加しない。新しい操作の登録・接続状態は未確認である。

## 互換性とデータ保全

v1を読み、最初の成功した保存でv2へ移行する。v2は `associations` に鍵と接続先の組を持つ。旧登録履歴は変換元にせず、固定ID・値・中断記録・削除済み鍵情報を保持する。読み取りだけでは移行も移行用コピー作成も行わない。

旧リモート操作と設定編集は読み取り専用で自動再開しない。旧削除途中の鍵は手動確認が必要なため使用を拒否するが、その記録だけで他の鍵の操作を止めない。旧記録を成功・完了へ自動変更しない。既存鍵、専用config、Include、既存バックアップはそのまま残す。

状態検証、排他ロック、原子的保存、鍵の上書き防止・同一性検証を維持する。`state.json.bak` は保存直前の正当な状態の正確なコピーだが、各保存で更新される。1操作内の再保存でもv1を失い得るため、ダウングレード用の恒久バックアップとはしない。旧版へ戻す可能性があれば、利用者がv0.5.0以降で最初の変更操作を行う前にアプリを終了してv1状態を別途保管し、戻す際に移行後の追加データを確認する。

## 影響

CLIの登録・解除・削除コマンド、認証・設定編集フラグと旧JSONの列挙形は意図的に非互換となる。0.xの非互換変更としてv0.5.0へMINORを更新し、v0.4.0以前へ遡って契約を適用しない。移行時は最初の変更前にv1状態を退避する。

リモート副作用とその確認・復旧を維持する負担が減る。利用者は公開鍵の配置・解除、SSH設定への貼り付け、必要ならローカルファイル整理を自分で行う。ガイド表示は作業完了の証拠にならない。既存Includeが残るため、過去の設定が有効なままの場合がある。

配布は同じ6ターゲットのPortableアーカイブとSHA256SUMS、ソース配信インストーラーを維持する。既存のGo・梱包・インストーラー検証に加え、v1非変更読込、v2移行、履歴保持、対象鍵だけの削除ブロック、読み取りの非変更性を確認する。結果は対象コミット・環境・限界とともに `docs/verification.md` へ追記し、過去の記録は書き換えない。
