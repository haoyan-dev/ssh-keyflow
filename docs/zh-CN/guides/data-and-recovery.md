## 保存位置与备份保存

管理信息保存在 `~/.ssh/ssh-keyflow/state.json`，生成的密钥保存在同一目录的 `keys/` 中，固定的主机公钥保存在 `known_hosts` 中。`known_hosts` 是独立于状态模式（schema）的文件，旧版本不会读取它。导入时引用明确指定的文件，不会移动或改写原文件。应用会验证公钥指纹和私钥文件的摘要，如果不一致或无法读取，会作为需要确认的问题停止。私钥内容和口令不会保存到状态 JSON 或参数中。

更新或迁移前，请退出应用，并将 `~/.ssh/ssh-keyflow/` 另行保存到受访问限制的其他位置。仅靠状态 JSON 无法恢复私钥。导入密钥的原文件以及你自己设置的 SSH config，也请根据需要另行保存。包含私钥的副本不要放在公开仓库或共享日志中。

恢复前也请先转移当前数据，并确认所用版本能读取保存的状态。请确认恢复后的路径与密钥指纹一致，并核对迁移后新增的密钥、连接目标和关联。应用没有自动恢复、状态合并或转换回旧模式的功能。

## 中断与上一状态

密钥创建使用原生 `ssh-keygen`，不会覆盖已有路径。如果创建中断，请使用 `keys list` 中的创建 ID 运行 `resume`。应用会将保存的路径、指纹和摘要与文件进行核对，在不自动删除部分生成文件的前提下继续创建。存在未完成的创建时，不会新建其他密钥对。状态变更受排他锁保护：先将经过验证的上一状态保存到 `state.json.bak`，再进行原子替换。不明的锁或无效的状态不会被自动修复。

## 从旧版本迁移与降级

v0.5.0 的简化是有意引入的不兼容变更。原有的 `register`、`unregister`、`registrations list`、`keys delete` 以及 `--new-key`、`--auth`、`--identity`、`--configure` 已不可用。旧的编号菜单、Tasks 以及递归的 SSH 设置搜索也已废弃。与现有 `Host` / Include / 通配符设置之间的重复和优先级，请在粘贴片段前由用户自行确认。

现有的 v1 状态在读取时不会被更改，首次保存状态时变为 v2。新的 `associations` 独立于旧注册历史。过去的注册、连接确认、设置编辑、删除历史和中断记录都会保留，不会被改写为当前的成功或完成。旧的远程操作是只读的，`resume` 不会接续它们。旧删除进行到一半的密钥需要手动确认，因此会被拒绝使用，但不影响其他密钥的操作。

**如果有可能回退到旧版本，请在 v0.5.0 及以后版本中执行第一次变更操作之前，退出应用并将 v1 的 `state.json` 另行保存到其他位置。** `state.json.bak` 是保存上一状态的滚动更新式备份，不会永久保留 v1。即使只是首次创建密钥也会多次保存状态，因此在同一操作中就可能被更新为 v2。旧版本无法读取 v2，因此降级时需要从另行保存的 v1 状态手动恢复，并核对迁移后新增的密钥、关联等内容。仅读取时不会自动创建迁移用副本。

过去生成的 `~/.ssh/ssh-keyflow/config`、普通的 `~/.ssh/config`、Include 和现有备份都不会被更改。残留的 Include 可能会继续加载原有设置，如有需要请由用户确认其内容。过去的验证结果请参阅[验证记录](../../verification.md)（日语），当前规格请参阅[应用契约](../reference/application-contract.md)。
