# 数据、迁移与恢复

## 保存位置与备份保存

管理信息保存在 `~/.ssh/ssh-keyflow/state.json`，生成的密钥保存在同一目录的 `keys/` 中。导入时引用明确指定的文件，不会移动或改写原文件。应用会验证公钥指纹和私钥文件的摘要，如果不一致或无法读取，会作为需要确认的问题停止。私钥内容和口令不会保存到状态 JSON 或参数中。

更新或迁移前，请退出应用，并将 `~/.ssh/ssh-keyflow/` 另行保存到受访问限制的其他位置。仅靠状态 JSON 无法恢复私钥。导入密钥的原文件以及你自己设置的 SSH config，也请根据需要另行保存。包含私钥的副本不要放在公开仓库或共享日志中。

恢复前也请先备份当前数据，并确认所用版本能读取保存的状态。请确认恢复后的路径与密钥指纹一致。应用没有自动恢复或状态合并的功能。

## 中断与上一状态

密钥创建使用原生 `ssh-keygen`，不会覆盖已有路径。如果创建中断，请使用 `keys list` 中的创建 ID 运行 `resume`。应用会将保存的路径、指纹和摘要与文件进行核对，在不自动删除部分生成文件的前提下继续创建。存在未完成的创建时，不会新建其他密钥对。状态变更受排他锁保护：先将经过验证的上一状态保存到 `state.json.bak`，再进行原子替换。不明的锁或无效的状态不会被自动修复。

## 从 v0.10.0 及更早版本迁移

v0.11.0 是只保留密钥对管理功能的有意不兼容变更。连接目标、关联、手动设置指南、主机密钥固定、TUI 和仅导入公钥的功能均已废弃。

v0.10.0 及更早版本的 `state.json`（模式 v1 / v2）仅读取时不会被更改。`keys list` 会在标准错误中显示下一次变更时哪些内容不会被沿用。变更操作在请求确认之前也会显示同样的内容。含有未知字段或损坏值的旧文件不会被读取，也不会进行任何更改。在首次变更操作（创建、导入、移除、恢复）中，应用按以下顺序处理：

1. 将原 `state.json` 原样写出到 `~/.ssh/ssh-keyflow/state.v<N>-<UTC时间>.json`。不会覆盖已有文件。如果写出失败，则不进行任何更改。重试中途失败的操作时，会复用内容相同的归档。
2. 只沿用带有私钥路径的密钥和未完成的密钥创建，并以模式 v3 保存。

不会沿用的内容包括：连接目标和关联、已移除的记录、旧的注册、设置、SSH config 编辑、引导和删除的记录与历史、仅有公钥的密钥，以及存在未完成旧密钥删除的密钥。这些内容保留在归档中。如果列出了未完成的 SSH config 编辑，请手动检查该文件。如果需要仅有公钥的密钥，请将其与对应的私钥配对，用 `keys import` 重新导入。

旧版本创建的 `~/.ssh/ssh-keyflow/known_hosts`（主机密钥固定文件）、`~/.ssh/ssh-keyflow/config`、普通的 `~/.ssh/config`、Include 以及从指南追加的 Host 块都不会被更改。用于固定的 `HostKeyAlias`、`UserKnownHostsFile` 和 `StrictHostKeyChecking` 行，只要文件保留，就会继续生效。如不再需要，请自行删除。

## 回退到旧版本

旧版本无法读取模式 v3。如需回退到旧版本，请先退出应用，然后执行以下操作：

1. 将当前的 `~/.ssh/ssh-keyflow/` 另行保存到其他位置。
2. 将 `state.v<N>-<UTC时间>.json` 恢复为名为 `state.json` 的文件。

迁移后创建或导入的密钥不包含在恢复的状态中。如有需要，请在旧版本中重新导入。`state.json.bak` 是保存上一状态的滚动更新式备份，迁移后会变为 v3，因此不能用于回退到旧版本。

过去的验证结果请参阅[验证记录](../../verification.md)（日语），当前规格请参阅[应用契约（中文概要）](../reference/application-contract.md)。
