# 文書の保守

[ドキュメント一覧](../README.md) · [コントリビューション](../../CONTRIBUTING.md)

文書はGitHubで読めるMarkdownとしてソースと同じPRで管理します。対応要件は簡体字中国語（`zh-CN`）、英語（`en`）、日本語（`ja`）です。コマンド・識別子・画面のラベルは実装の表記を使います。

## 対応言語の要件

README、文書索引、チュートリアル、操作・問題解決ガイド、コントリビューション、文書保守・公開ガイドを3言語で提供します。公開仕様の説明も各言語から参照できるようにし、契約と用語の正本は一元管理します。過去の研究・チケット・ADR・検証記録を遡って翻訳する必要はありません。

- READMEと各ページに `简体中文` / `English` / `日本語` の言語リンクを置き、同じ内容のページへ移動できるようにします。未翻訳のページでは不足とフォールバック先の言語を明示します。
- 既存のルートパスと公開済み見出しへのリンクを維持します。言語別のファイル配置は実装時に決定します。
- 前提条件、実行例、安全条件、移行・ダウングレードの限界を各言語で揃えます。コマンド、フラグ、JSONキー、パス、製品識別子は翻訳しません。
- 内容を変更するPRでは対応する翻訳も更新します。未翻訳・更新待ちは明示して追跡し、欠落したまま全言語対応済みとは表示しません。
- CIで3言語のリンク・見出し・言語間の対応・翻訳対象の充足を確認します。翻訳の用語と技術的な正確さは言語ごとにレビューします。

現在は日本語の文書構成を実装済みで、中国語・英語の翻訳と多言語用CI検証は未実装です。[仕様](../../.scratch/documentation-system/spec.md)と[翻訳チケット](../../.scratch/documentation-system/issues/04-multilingual-documentation.md)で追跡します。この要件は文書を対象とし、アプリのUI・CLIメッセージの翻訳は含みません。

## 配置と情報の所有

| 配置 | 読者と役割 | 更新のきっかけ |
| --- | --- | --- |
| `README.md` | 初めて訪れた人。目的、導入、次に読むページ | 製品の範囲・導入入口・主要ページの変更 |
| `docs/README.md` | 必要な手順を探す人。タスクと文書の索引 | ページの追加・移動・廃止 |
| `docs/tutorials/` | 初めて使う人。1つの結果までの順序付き手順 | 初回操作の変更 |
| `docs/guides/` | 目的のある利用者。反復する作業・問題解決 | 作業手順や制約の変更 |
| `docs/application-contract.md` | 利用者・自動化の作者。公開インターフェースの正確な約束 | CLI・JSON・互換性・配布要件の変更 |
| `GLOSSARY.md` / `docs/adr/` | 設計者。用語と判断の理由 | 用語・設計判断の追加や更新 |
| `CONTRIBUTING.md` / `docs/maintaining/` | コントリビューター・保守者。開発と公開 | チェック・レビュー・保守手順の変更 |
| `docs/verification.md` | レビュアー・保守者。時点ごとの検証証拠 | 検証・公開監査の完了 |
| `.scratch/<feature>/` | 作業者。研究・仕様・チケット・作業記録 | 機能単位の調査と進行 |

契約は `application-contract.md`、用語は用語集、公開の規則は `AGENTS.md` を正とします。ガイドは作業に必要な例を示し、全フラグやスキーマの複製を作りません。検証記録や過去のレビューは記録時点の情報で、現在の契約の代わりにはしません。

## ページを書く

- 冒頭に目的とドキュメント一覧への戻り先を置きます。
- チュートリアルには前提、操作する端末、置き換える値、実行手順、期待結果、次の作業を示します。
- ガイドには対象条件、作業、確認方法、復旧上の注意を必要な場所に記載します。
- コードブロックに `sh` / `powershell` などの言語を指定します。シェルのプロンプト文字をコマンドへ混ぜません。
- 例は実在するコマンドに合わせます。固定バージョンが指定方法の例なら、その旨を明示します。
- 秘密鍵や認証情報は掲載しません。生成・表示と実行、管理からの削除とアクセス失効、ビルドと実機検証を区別します。
- 内部リンクは相対パスを使い、移動時は既存のリンク元を確認します。公開済み見出しは可能な範囲で案内を残します。

## PRの確認

1. [索引](../README.md)から新しいページへ進めることを確認します。
2. `python scripts/check_docs.py` を実行し、リンク先と見出しを検証します。このチェックはネットワークを使わず、外部URLの応答は確認しません。
3. Markdownプレビューで見出し、表、コードブロック、ページ間の導線を確認します。コマンド例は契約・`--help`・影響するテストと照合します。
4. 規約レビューでは配置、言語、用語、情報の所有、既存リンクを確認します。仕様レビューではチケットの完了条件と利用者が手順を完了できるかを別に確認します。
5. 検証したSHA・環境・結果・限界をPRへ記録し、未検証事項を成功として扱いません。

チェッカーの対象はREADME、CONTRIBUTING、用語集、AGENTS、および索引・tutorials・guides・maintaining・ADR・エージェント運用文書・アプリケーション契約です。履歴文書と `.scratch/` はリンク先の存在を確認しますが、古い内容を再帰的に現行仕様へ書き換えません。新しい文書群を追加したときは `scripts/check_docs.py` の対象も更新してください。

文書だけの変更は通常のレビューPRとして公開します。アプリケーションの版・タグ・配布物は[既存の公開手順](releases.md)で扱います。
