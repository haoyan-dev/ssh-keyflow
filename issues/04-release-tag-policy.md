# 04 タグ付けの承認と検証方針を簡潔にする

## Objective

「mainへマージしてバージョンをタグ付け」という依頼から、規則に沿った版・対象SHAの決定、タグpush、自動公開、公開物検証まで進められるようにする。版とSHAをエージェントが選んだことだけを理由に追加確認を求めない。

## Scope

`AGENTS.md` のタグ規定と `docs/application-contract.md` の参照を更新する。既存タグ・公開物・ワークフローは変更せず、このポリシー見直し自体ではリリースしない。

## Acceptance criteria

- [x] 明示的なタグ付け依頼、ローカル限定、方針見直し、実装依頼の承認範囲を区別する。
- [x] 未指定の版はSemVer規則で選び、対象は依頼作業が統合された最新origin/mainを原則とする。push前に版・完全SHAを報告する。
- [x] 指定版・指定SHAが規定を満たさない場合や、範囲・リスクが実質的に変わる場合の確認を残す。
- [x] 同一ツリー・検証入力が不変なら証拠を再利用し、必要なCIと変更影響の検証を維持する。
- [x] 公開タグ・バイナリの不変性、公開後の配布物確認と記録を維持する。
- [x] アプリケーション契約の独立した版・SHA承認要求を除き、規定の参照先を一本化する。

## Decision cases

| 依頼・条件 | 期待する行動 |
| --- | --- |
| mainへマージ、バージョンをタグ付け | 版・SHAを選んで報告し、追加承認なしでpushと自動公開まで進める |
| ローカルタグだけ作成 | タグをローカルに作成する |
| タグ付けポリシーを見直す / 機能を実装する | 依頼された変更を行う。リリース承認とは扱わない |
| 明示指定の版が使用済み / SHAがmain未統合 | 公開を止め、使用可能な版・対象への変更を確認する |
| 同一ツリーのマージコミット / 記録文書だけの追加 | 検証入力の比較を残して既存証拠を再利用し、必要なCIは維持する |
| ソース・依存・ビルド入力・実行条件に差分 | 影響する検証を再実行する |
| 公開後の検証記録を追加 | 文書PRへ記録し、公開タグは維持する |
