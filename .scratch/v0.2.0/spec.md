# v0.2.0: TUI・CLIとPortable配布

Status: ready-for-agent

合意日：2026-11-06
検証境界：ユーザー確認済み

## Problem Statement

利用者はSSH接続に使う鍵、接続先、公開鍵の登録と登録履歴を、一覧で把握しながら操作したい。現行の番号選択メニューと長い質問列では、状態を見渡して必要な操作へ進むことや、対象を引数で直接指定することが難しい。

また、インストーラーを実行せず、配布物を展開して使い始め、本体の差し替えだけで更新したい。既存の鍵・管理情報・SSH設定・公開鍵登録を引き継ぎ、本体の配置と管理データの保存を独立して扱う必要がある。

開発では、TUIやCLIの基盤を自作する負担を避け、既存の処理とライブラリを活用して必要な機能を最小限の変更で提供したい。

## Solution

一覧中心のTUIと、操作・対象・設定を引数で指定するCLIを提供する。TUIでは接続先・鍵・登録履歴から必要な操作へ進み、CLIでは同じ主要操作を直接実行できる。一覧には機械可読のJSON出力も用意する。

両方の入口から同じアプリケーション処理を利用し、既存の状態検証、承認、登録解除とローカル鍵の削除の区別、中断後の再開を引き継ぐ。秘密値の入力と認証は引き続きOSのOpenSSHに任せる。

配布は6対象のPortableアーカイブに統一し、インストーラーを廃止する。利用者は展開して起動し、更新時にはアプリを終了して本体を差し替える。Portableは本体の配置を自由に選べることを意味し、管理データの持ち運びは含めない。

## User Stories

1. 利用者として、端末で引数なしで起動してTUIを開きたい。それにより、コマンドを覚えずに操作を始められる。
2. 利用者として、TUIを明示的に指定して起動したい。それにより、利用する操作方法を選べる。
3. 利用者として、接続先の一覧を確認したい。それにより、公開鍵を登録する端末とログイン先ユーザーを把握できる。
4. 利用者として、鍵の一覧と詳細を確認したい。それにより、利用する鍵を選べる。
5. 利用者として、登録履歴を確認したい。それにより、どの公開鍵をどの接続先に登録・解除したかを把握できる。
6. 利用者として、登録履歴、登録状態、接続確認、操作進捗を区別して確認したい。それにより、記録だけから接続可能と誤認せずに判断できる。
7. 利用者として、管理対象と管理対象外を区別して確認したい。それにより、既存の鍵や設定を意図せず変更することを避けられる。
8. 利用者として、一覧で対象を選んで詳細と操作を開きたい。それにより、長い質問列を繰り返さずに目的の操作へ進める。
9. 利用者として、フォームと選択部品で接続先や鍵の情報を入力したい。それにより、入力内容を確認しながら操作できる。
10. 利用者として、キーボードでTUIを操作してヘルプを確認したい。それにより、操作方法を画面上で把握できる。
11. 利用者として、端末幅が狭い場合やサイズ変更後も操作と確認内容を読みたい。それにより、端末の大きさに応じて利用できる。
12. 利用者として、実行前に変更対象と変更内容を確認したい。それにより、意図した変更だけを承認できる。
13. 利用者として、入力中に戻る・キャンセルを選びたい。それにより、実行前の変更を取りやめられる。
14. 利用者として、新しい接続先を追加したい。それにより、その接続先に使う鍵と公開鍵登録を管理できる。
15. 利用者として、Ed25519鍵を新規作成したい。それにより、接続先に使う鍵を準備できる。
16. 利用者として、既存の鍵のペアまたは公開鍵だけを明示的に取り込みたい。それにより、元のファイルを移動せずに管理対象へ追加できる。
17. 利用者として、既存の管理対象の鍵を再利用したい。それにより、接続先追加時に不要な鍵を増やさずに済む。
18. 利用者として、接続先へ公開鍵を登録したい。それにより、指定した鍵でのSSH接続を準備できる。
19. 利用者として、登録後に指定した秘密鍵だけで接続確認を行いたい。それにより、別の認証の成功と対象鍵の成功を区別できる。
20. 利用者として、自動登録できない場合は接続先OSに合った手動手順を確認したい。それにより、自分で設定を続けられる。
21. 利用者として、生成するSSH設定と既存設定へのInclude追加を確認・承認したい。それにより、意図しない設定変更を避けられる。
22. 利用者として、指定した接続先から指定した公開鍵の登録を解除したい。それにより、不要になった接続権限を取り除ける。
23. 利用者として、登録解除前に別の認証による新規接続を確認したい。それにより、解除後の接続手段を確保できる。
24. 利用者として、ローカル鍵の削除を登録解除とは別に実行したい。それにより、接続先の登録と手元のファイルを区別して管理できる。
25. 利用者として、登録先が残る場合や管理記録とファイルが一致しない場合は削除を止めてほしい。それにより、確認できていない鍵を失わずに済む。
26. 利用者として、作成途中の鍵や中断した操作を確認して再開したい。それにより、既存の意図と進捗を引き継いで操作できる。
27. 利用者として、結果不明の操作を実状態と照合してから再開したい。それにより、重複登録や誤った成功記録を避けられる。
28. 利用者として、認証と鍵生成ではOpenSSHへ直接秘密値を入力したい。それにより、アプリの引数や保存データに秘密値を残さずに済む。
29. 利用者として、認証や鍵生成の終了・失敗・中断後にTUIへ戻りたい。それにより、端末を復旧して操作結果を確認できる。
30. CLI利用者として、対象と設定を引数で直接指定したい。それにより、番号選択メニューを経由せずに操作できる。
31. CLI利用者として、接続先・鍵・登録履歴の一覧をJSONで取得したい。それにより、他のツールで結果を利用できる。
32. CLI利用者として、JSON結果と診断を別の出力先で受け取りたい。それにより、診断が混ざらないデータを処理できる。
33. CLI利用者として、入力不足・不正・曖昧な対象を変更前に検出してほしい。それにより、誤った対象への変更を防げる。
34. CLI利用者として、コマンドの使い方と対象の指定方法をヘルプで確認したい。それにより、固定IDや別名を正しく使える。
35. CLI利用者として、成功・実行失敗・使用法エラーを終了コードで判定したい。それにより、呼び出し元で結果に応じた処理ができる。
36. CLI利用者として、ヘルプとバージョンを管理データの初期化なしに表示したい。それにより、環境を変更せずに情報を確認できる。
37. CLI利用者として、読み取り専用の一覧をSSHコマンドや書き込みなしに利用したい。それにより、情報確認だけを行える。
38. CLI利用者として、端末がない場合は認証・確認に端末が必要な操作を変更前に止めてほしい。それにより、入力待ちや意図しない変更を避けられる。
39. CLI利用者として、非端末で引数なしで呼び出した場合はヘルプを受け取りたい。それにより、TUIの起動で処理が止まることを避けられる。
40. 利用者として、TUIとCLIで同じ処理と安全条件を使いたい。それにより、入口を変えても一貫した結果を得られる。
41. 利用者として、自分のOSとCPUに合った配布物を選びたい。それにより、Goを導入せずに実行できる。
42. 利用者として、アーカイブを展開して起動したい。それにより、インストーラーを実行せずに使い始められる。
43. 利用者として、チェックサムでアーカイブの整合性を確認したい。それにより、取得した配布物を検証できる。
44. 利用者として、本体を任意の場所に配置・移動したい。それにより、本体の配置を自分で管理できる。
45. 利用者として、本体の配置を変えても既存の鍵・管理情報・生成設定を使いたい。それにより、データを移行せずに利用を続けられる。
46. 利用者として、アプリ終了後に本体を差し替えて更新したい。それにより、管理データを保持して新しい版へ移行できる。
47. 利用者として、本体を削除しても鍵・設定・登録履歴・接続先の公開鍵登録を保持したい。それにより、アプリの削除と鍵の削除や登録解除を区別できる。
48. 利用者として、必要な場合に自分でPATHを設定したい。それにより、環境の変更範囲を把握できる。
49. 旧インストーラーの利用者として、手動更新の手順と旧所有記録の扱いを確認したい。それにより、既存の配置とデータを理解したうえで移行できる。
50. 利用者として、OS側のOpenSSHが必要なことを導入案内で確認したい。それにより、必要な環境を準備できる。
51. 開発者として、TUI部品とコマンド解析に既存ライブラリを利用したい。それにより、独自基盤の実装と保守を減らせる。
52. 開発者として、既存の状態管理・SSH処理・テストを再利用したい。それにより、既存の安全条件を保ちながら入口を変更できる。
53. 開発者として、クロスビルドの成功と実機動作確認を区別して記録したい。それにより、検証範囲を正確に伝えられる。

## Implementation Decisions

- Go 1.26の既存アプリケーション処理、永続状態、外部SSH操作の構成を活用し、番号選択・質問列への依存を必要な範囲で分離する。
- TUIとCLIは構造化された入力で同じ処理を呼ぶ。状態検証、変更全体の排他、変更前の意図保存、結果不明時の照合、設定差分・バックアップ・承認、解除時の別認証確認、ローカル削除条件を維持する。
- 管理対象と管理対象外、登録解除とローカル鍵の削除、登録履歴・登録状態・接続確認・進捗の区別を維持する。
- 既存データを継続利用し、UI・CLI変更のためだけに状態スキーマを変更しない。既存の絶対パス参照と保存先を引き継ぐ。

**ライブラリ利用**

既存コードと標準ライブラリで十分な部分は再利用する。端末制御、UI部品、コマンド解析など、まとまった仕組みが必要な部分は以下の既存ライブラリを採用する方針とする。

| 用途 | 利用方針 |
| --- | --- |
| TUIのイベント処理・画面制御 | Bubble Tea |
| 一覧・テキスト入力・ヘルプ等 | Bubblesの必要な部品 |
| TUIの配置・表示スタイル | Lip Gloss |
| CLIのサブコマンド・フラグ・ヘルプ | Cobra |
| JSON・プロセス実行・ファイル操作 | Go標準ライブラリと既存コード |
| SSH通信・秘密値の入力・鍵生成 | 現行どおりOSのOpenSSH |
| リリース梱包 | 現行のビルド・梱包処理を必要な範囲で修正 |

ライブラリを包む汎用フレームワーク、独自ウィジェット群、独自CLIパーサーは作らない。Ponytailの方針を適用し、必要なアプリケーション処理と画面・コマンドの接続部分だけを書く。依存追加時に互換性のある安定版とメジャーバージョンの組み合わせを確認して固定し、Go 1.26・6対象・CGO無効でのビルドとライセンス表記を確認する。

**TUI**

- 端末での引数なし起動、または `ssh-keyflow tui` で起動する。
- 接続先・鍵・登録履歴の一覧を起点に、対象の詳細、追加、登録、登録解除、ローカル鍵の削除へ進める。
- 作成途中・結果不明・要確認の状態を表示し、既存の再開・手動手順を利用できる。
- 入力にはフォームと選択部品を使い、長い番号選択の質問列を置き換える。
- 変更前に対象と変更内容を表示し、必要な承認を取得する。戻る・キャンセルだけでは変更を実行しない。
- キーボードで操作でき、ヘルプを表示する。端末幅が狭い場合にも操作と確認内容が読める。
- OpenSSHの認証・鍵生成時はTUIの端末制御を解除し、元の端末を子プロセスへ渡す。終了・失敗・中断後に端末を復元し、保存済みの実状態から表示を更新する。入力の先読みで秘密値を消費しない。

**CLI**

`hosts list`、`hosts add`、`keys list`、`keys create`、`keys import`、`keys delete`、`registrations list`、`register`、`unregister`、`resume` をコマンド構成の基準とする。一覧は `--json` に対応する。具体的なフラグと再開対象の指定方法は実装時にヘルプと公開契約へ記録する。

- 対象・設定は引数で指定する。入力不足時に番号選択メニューへ移行せず、エラーと使い方を表示する。
- 表示名・別名と固定IDの使い分けをヘルプで定義し、曖昧な対象を自動選択しない。
- 登録時の接続確認、設定生成とIncludeの承認、既存の作成・登録・削除の再開、手動手順への切り替えをCLIからも利用できる。
- 変更操作の確認とOpenSSHの認証は端末対話を許可する。端末が必要な操作は、端末がない場合に副作用の前に失敗させる。汎用の `--yes` による確認省略は本バージョンに追加しない。
- CLIとTUIは同じアプリケーション処理を呼び出す。メニュー回答を文字列として組み立てて既存処理へ流し込む実装はしない。
- 一覧の `--json` は機械可読JSONだけを標準出力へ出し、診断は標準エラー出力へ出す。秘密鍵本文や秘密値を含めない。
- 終了コードは成功0、実行失敗1、引数・使用法エラー2とする。CLI操作のキャンセルや未確認を成功扱いにしない。TUIの通常終了は成功とする。
- `--help` と `--version` は保存先・SSH依存の確認や初期化を行わない。非端末での引数なし起動はヘルプを表示して終了0とし、明示的な `tui` は使用法エラー2とする。
- 読み取り専用の一覧は、SSHコマンドや保存先への書き込みを要求しない。破損状態を空データとして表示しない。

**Portable配布**

- Windows/Linux/macOSのamd64/arm64の6対象を維持する。
- Windowsはzip、Linux/macOSはtar.gzとし、展開した実行ファイルを直接起動できる。Goの導入は不要。
- 本バージョンのPortableは「実行ファイルの配置場所を自由に選べる」を意味する。鍵・管理情報・生成設定は引き続きユーザーのホーム配下の従来の専用SSH管理領域に保存する。実行ファイルの移動で保存先を変更しない。
- `ssh` と `ssh-keygen` はOS側のものを利用し、同梱しない。
- 更新はアプリを終了して実行ファイルを差し替える。自動更新、インストーラー、PATHの自動変更は提供しない。
- 実行ファイルの削除・移動・差し替えでは鍵、管理情報、SSH設定、接続先の公開鍵登録を変更しない。
- 配布物は6アーカイブとSHA256SUMS。manifestは6アーカイブを対象にする。依存ライセンス上必要な文書はアーカイブに同梱し、梱包テストで許可するメンバーを明示する。チェックサムは署名検証とは扱わない。
- インストーラーと専用テスト・案内を整理し、v0.2.0のリリースにはインストーラーを添付しない。
- 旧インストーラーで導入した利用者向けに、既存配置先への手動差し替えと旧所有記録の関係を説明する。旧スクリプトは差し替え後の実行ファイルを拒否し得るため、手動差し替え後の更新・削除は手動で行う。既存のPATH設定・所有記録を新アプリが自動で書き換えない。
- README、CI、リリース定義、検証記録を新しい配布契約へ揃える。

## Testing Decisions

- ユーザー確認済みの検証境界を採用する。主な振る舞いテストは現行の `app.Run` 相当の公開アプリケーション境界へ集約し、CLI・TUIごとに共通処理のテストを重複させない。
- 既存の一時ホーム、入出力、外部コマンド実行の `Runner` 境界を再利用する。内部の状態層やSSH処理を細かくモックせず、外部プロセス境界で応答や失敗を与える。実ユーザーのSSHデータや未指定の接続先は使わない。
- 良いテストは公開操作への入力に対し、表示・出力・保存データ・ファイルへの影響・外部操作の対象を確認する。内部関数の呼び順、構造体の分割、ライブラリ内部や装飾の細部を固定しない。
- 既存のアプリケーションテストを先例とし、鍵の作成・取り込み、接続先追加、登録、解除、ローカル削除、設定生成、中断・再開、排他、破損状態、管理対象外の保持、整合性不一致の振る舞いを新境界へ適応する。
- 登録・解除スクリプトやOpenSSH引数には、既存の隔離fixtureによる実行検証を必要な範囲で維持する。代替応答だけでOS固有の実動作を確認済みとはしない。
- CLIの入口では引数解析、対象解決、ヘルプ、JSONと診断の分離、終了コード、非端末時の振る舞いを検証する。ヘルプ・バージョンで保存先が初期化されず、一覧で書き込みやSSH依存が要求されないことを確認する。
- TUIの入口では一覧からの選択・詳細・操作・確認・キャンセル、再開、リサイズを確認する。ライブラリ内部を再検証する独自テスト基盤は作らない。
- OpenSSHへの端末受け渡しと終了・失敗・中断後の復元は実端末でも検証する。秘密値の横取りや保存がないことを確認し、代替Runnerによる確認と実端末での確認を区別して記録する。
- 変更前のキャンセルは副作用なしを確認する。副作用開始後の失敗・中断では完了済み処理を取り消したと装わず、意図・進捗と結果不明状態を保持して照合・再開できることを確認する。
- 配布物は梱包コマンドと生成アーカイブの境界で検証する。既存のPython標準ライブラリによるfixture、配布物生成、SSHデータの変更前後比較を参考にし、不要になるインストーラーのHTTP取得・配置テストは引き継がない。
- 6対象のアーカイブ名と許可する同梱物、実行権限、ライセンス文書、チェックサム、バージョン注入、既存出力を上書きしないことを確認する。実行可能な対象では展開後の起動を確認し、本体の移動・差し替え・削除で既存データが変わらないことも検証する。
- Goテスト、Portable梱包テスト、CGO無効の6対象クロスビルドをCIへ組み込む。対象OS・CPUでの実機確認とは区別し、未確認の対象を検証記録へ明記する。
- 旧番号メニュー固有の期待値は置き換え、処理・データ保護の振る舞いテストは維持する。変更に対応する確認が通った後は、新たな変更や懸念がない限り同じ確認を繰り返さない。

## Out of Scope

- データを実行ファイルの隣に置くモード、データフォルダ移動、相対パスへの移行。
- OpenSSHの同梱、独自SSH実装、パスワードやパスフレーズの引数・保存・ログ出力。
- 完全な無人実行、自動更新、新しい配布基盤、プラグイン機構。
- 接続先・鍵の名前変更や汎用編集など、既存操作を超える機能。
- 実機の変更、タグ作成、リリース公開。この仕様作成はそれらの実行許可を意味しない。

## Further Notes

- 本仕様は会話で合意した方針とユーザー確認済みの検証境界を統合したもの。実装完了の記録ではない。
- [従来仕様](../ssh-onboarding/spec.md) の番号選択メニューとインストーラー要件を本仕様で置き換える。「非対話・JSONコマンドは別途検討」のうち、直接指定CLIと一覧JSONを本バージョンへ取り込む。完全な無人実行は対象外のままとする。
- [従来の公開契約](../../docs/application-contract.md) の「標準ライブラリのみ」、引数制約、対話入力とアプリケーション境界は実装時に更新する。用語と既存のデータ保護要件は引き継ぐ。
- 既存データで主要操作を両方の入口から利用でき、上記の振る舞い・端末・配布検証が完了したことを本バージョンの完了条件とする。
- 仕様と既存の4チケットの状態は `ready-for-agent` とする。各チケットの依存関係に従い、重複するチケットは作成しない。
