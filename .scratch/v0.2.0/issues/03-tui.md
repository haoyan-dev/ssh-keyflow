# 03: Bubble Teaによる一覧中心のTUI

Status: ready-for-human
Resolution: completed
Blocked by: 01, 02

## What to build

[spec.md](../spec.md) に従い、Bubble Tea・Bubbles・Lip Glossを利用して番号選択メニューを置き換える。02の起動分岐へTUIを接続する。

## Acceptance criteria

- [x] 端末での引数なし起動と明示的なtui起動で、接続先・鍵・登録履歴の一覧を表示する。
- [x] 一覧・詳細から既存主要操作、作成途中や結果不明の処理の再開、手動手順へ進める。
- [x] 入力・選択・ヘルプには既存部品を使い、長い番号選択の質問列を廃止する。
- [x] 変更対象と内容を実行前に確認でき、戻る・キャンセルで変更しない。
- [x] OpenSSHへ元の端末を渡し、成功・失敗・中断後に端末と表示を復元する。秘密値をTUI側で保持しない。
- [x] リサイズ、狭い端末、キーボード操作と終了を確認する。
- [x] 共通処理を使い、画面遷移・キャンセルと端末受け渡しの検証を行う。実端末での確認結果と自動テストを区別して記録する。

## Resolution

Bubble Tea v2.1.1、Bubbles v2.2.1、Lip Gloss v2.0.6を固定し、一覧・詳細・入力・確認・結果画面を実装した。既存のCLI起動分岐へ接続し、操作は構造化した `app.Request` で共通処理へ渡す。端末の解放と復元は `tea.Exec` を利用する。作成・インポート・接続先追加・登録・解除・ローカル削除・再開に対応し、認証の既定値は手動手順とした。

自動検証：公開入口 `tui.NewProgram` とBubble Tea公開イベントを通じて、読み取り専用起動、フォームのキャンセル、詳細と未管理候補、登録レコードからの対象入力、32×12の表示を確認した。`go test ./...`、`go vet ./...` が成功。`CGO_ENABLED=0` のWindows/Linux/macOS × amd64/arm64の6対象ビルドが成功した。

実端末検証：隔離ホームを使ったWindows PTYで、引数なし起動と明示的tui起動、一覧移動、フォームと確認、ネイティブOpenSSHによるEd25519作成、パスフレーズ入力中のCtrl-C、同じ作成ID・パスへの再開と成功、失敗後の復元、qによる正常終了を確認した。80×24→32×12→50×18のリサイズも確認した。存在しない公開鍵のインポート失敗では、状態ファイルのハッシュが変わらなかった。

検証の範囲：実ユーザーの `.ssh` やリモートサーバーは変更していない。実SSHサーバーとの認証、Windows管理者の共有領域、Linux/macOS実端末は未検証。クロスビルドはコンパイルの証拠であり、各OSの実行検証ではない。
