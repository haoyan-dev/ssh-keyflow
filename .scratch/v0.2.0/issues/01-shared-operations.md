# 01: TUI・CLI共通処理とライブラリ導入

Status: ready-for-agent
Blocked by: None

## What to build

[spec.md](../spec.md) に従い、既存アプリケーション処理から番号選択・質問列への依存を分離する。既存の状態管理・SSH処理を再利用し、TUIとCLIが構造化された入力で同じ操作を呼べるようにする。必要な確認とOpenSSHの端末入力の境界を残す。

## Acceptance criteria

- [ ] 鍵の作成・取り込み・削除、接続先追加、登録・解除、一覧、再開、設定生成・手動手順を共通処理として利用できる。
- [ ] 意図保存、変更全体の排他、整合性確認、結果不明時の照合、承認条件を維持する。
- [ ] 旧メニュー回答の疑似入力で処理を再利用せず、不要な汎用フレームワークを導入しない。
- [ ] 必要な依存の互換性ある安定版を公式資料で確認して固定し、Go 1.26・CGO_ENABLED=0・6対象のビルドとライセンス条件を確認する。
- [ ] 既存の処理・データ保護の振る舞いテストを新境界へ適応し、主要な成功・失敗・再開が通る。
- [ ] ユーザー確認済みの検証境界に従い、現行app.Run相当の公開操作、一時home、既存Runnerで外から観測できる結果を検証する。内部層ごとのモックを追加しない。
- [ ] docs/application-contract.mdを共通処理と端末受け渡しの契約へ更新する。
