# 01: TUI・CLI共通処理とライブラリ導入

Status: ready-for-agent
Resolution: completed
Blocked by: None

## What to build

[spec.md](../spec.md) に従い、既存アプリケーション処理から番号選択・質問列への依存を分離する。既存の状態管理・SSH処理を再利用し、TUIとCLIが構造化された入力で同じ操作を呼べるようにする。必要な確認とOpenSSHの端末入力の境界を残す。

## Acceptance criteria

- [x] 鍵の作成・取り込み・削除、接続先追加、登録・解除、一覧、再開、設定生成・手動手順を共通処理として利用できる。
- [x] 意図保存、変更全体の排他、整合性確認、結果不明時の照合、承認条件を維持する。
- [x] 旧メニュー回答の疑似入力で処理を再利用せず、不要な汎用フレームワークを導入しない。
- [x] 必要な依存の互換性ある安定版を公式資料で確認して固定し、Go 1.26・CGO_ENABLED=0・6対象のビルドとライセンス条件を確認する。共通処理には新規依存不要のため、利用段階のCLI・TUIチケットで追加・検証する。
- [x] 既存の処理・データ保護の振る舞いテストを新境界へ適応し、主要な成功・失敗・再開が通る。
- [x] ユーザー確認済みの検証境界に従い、現行app.Run相当の公開操作、一時home、既存Runnerで外から観測できる結果を検証する。内部層ごとのモックを追加しない。
- [x] docs/application-contract.mdを共通処理と端末受け渡しの契約へ更新する。

## Resolution

completed (2026-11-06): `Options.Request`による直接操作、`Confirm`承認、読み取り専用`Snapshot`を追加。既存のSSH・状態管理を再利用し、作成・取り込み・接続先追加・登録・解除・ローカル削除・固定IDによる再開を公開境界から利用できる。番号メニューは後続チケットが起動点を切り替えるまで互換テスト用に保持する。

- TDD: 直接一覧・取り込み、作成と削除、接続先追加、登録・再開・解除の各スライスで未実装による失敗を確認して実装した。入力不正が保存先を作る失敗を確認し、副作用前の検証へ修正した。
- 構造化操作の確認拒否は`ErrCancelled`を返し、元ファイルと未保存状態を保持する。元の端末入力をRunnerへ渡し、認証値はRequestに含めない。
- 自動操作失敗時は手動手順を残しつつエラーを返す。明示的な手動手順要求は結果不明状態を保持して正常に表示する。
- 共通処理は標準ライブラリと既存コードだけで実装。依存追加は実際に使用するCLI・TUIチケットへ委ねる。
- 検証: `go test ./...`成功（app 43.229秒、cmdとsshは成功済みキャッシュ）。構造化操作テストは一覧・取り込み・作成と削除・接続先追加と手動登録/再開/解除・承認キャンセル・不正認証・自動登録と設定承認を確認。`git diff --check`成功。
- 今回は実端末・実機接続を利用していない。端末制御はTUIチケット、依存を含む6対象ビルドはCLI/TUI・Portableチケットで検証する。
