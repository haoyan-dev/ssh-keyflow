# SSH KeyFlow — 設計中の仕様

Status: ready-for-human
Released: v0.1.0（`ee3a00f`）。自動登録・解除はv0.5.0（`6a09684`、PR #8、ADR 0001）で廃止

会話で合意した要件を記録する。未決定事項は実装上の確定事項として扱わない。

## 名称

- 正式な表示名は SSH KeyFlow とする。
- リポジトリ名とコマンド名は ssh-keyflow とし、Windows の実行ファイル名は ssh-keyflow.exe とする。
- ssh-onboarding は仮称として廃止し、今後の実装と配布には正式名を使う。

## 目的

VPS、Tailscale 内の端末、ノートPC、メインPCへの SSH 公開鍵登録と、自分の鍵の管理を行う小さな CLI を作る。

## 合意済みの範囲

- 登録先は Windows、Linux、macOS。
- ローカルの鍵と、自分の公開鍵の登録・解除を管理する。他人の鍵の管理は対象外。
- 本体はバイナリ配布を前提とし、GitHub Releases から install.sh / install.ps1 でインストールする。
- 起動時に環境チェックを行う。ssh、ssh-keygen が不足していれば OS 別の導入手順とコピペ用コマンドを案内し、再チェックできるようにする。
- 保存先への書き込みと、既存の管理用 JSON の読み込みを確認する。読み込めない場合は更新を止める。
- 引数なしの起動では対話メニューを表示する。

## 登録の流れ

1. 接続先、別名、ユーザー名、公開鍵を指定する。ポートは省略可能とする。
2. 既存鍵を選ぶか、新しく作成する。鍵のファイル名は自動生成し、既存ファイルを上書きしない。
3. 新規作成は接続先ごとに1組を標準とする。同じ鍵を複数の接続先で使うことも可能。
4. 新規鍵のパスフレーズ入力を促す。空欄も許可し、値は管理 JSON に保存しない。
5. パスワードまたは既存の鍵で接続できれば、公開鍵を自動登録する。同じ鍵を重複登録しない。
6. 接続できなければ、接続先に応じた手順と公開鍵を含むコピペ用コマンドを表示する。SSH 自体の有効化手順も案内する。
7. 登録した鍵で接続を確認し、別名で接続するための設定を保存する。

## Tailscale の対応範囲

- Tailscale は通常の SSH サーバーへの接続経路として扱う。
- Tailscale の IP アドレスまたは端末名を接続先として入力できるようにする。
- 公開鍵の登録先は通常の SSH サーバーとする。
- Tailscale SSH 固有の認証・認可、Tailscale 自体の設定とポリシー変更は初版に含めない。

## 接続先の確認と認証入力

- 初回接続ではホスト鍵の指紋を表示し、ユーザーの承認を求める。
- 記録済みのホスト鍵と異なる場合は処理を止め、確認手順を案内する。
- 接続を続けるために既存のホスト鍵の記録を自動削除しない。
- パスワードとパスフレーズの入力は ssh / ssh-keygen の対話入力に任せる。
- 認証情報を JSON、操作ログ、コマンド引数に保存しない。

## 新規鍵の方式と命名

- 新規作成する鍵の方式は Ed25519 に統一する。
- ファイル名は id_ed25519_<別名>_<作成日時> とし、公開鍵には .pub を付ける。
- 保存先は ~/.ssh/ssh-keyflow/keys/ とする。
- 名前が重複する場合は連番を追加し、既存ファイルを上書きしない。
- 表示用の別名は保持し、ファイル名には安全な名前を生成して使う。
- 取り込む既存鍵は方式を変更しない。

## 対話メニュー

- 接続先の追加と公開鍵登録。
- 接続先と鍵の一覧表示。
- 既存の接続先への別の公開鍵の登録。
- 接続先からの公開鍵の登録解除。
- 鍵の作成と既存鍵の取り込み。
- ローカルの鍵ファイルの削除。

## 保存構成

管理情報は JSON を正とする。秘密鍵やパスワードそのものを JSON に保存しない。

```text
~/.ssh/
├── config
└── ssh-keyflow/
    ├── config
    ├── state.json
    └── keys/
```

- state.json に鍵の管理名、指紋、ファイルパス、接続先、登録履歴と確認結果を記録する。
- 専用の config を JSON から生成し、通常の config に読み込み設定を追加する。変更前に既存 config のバックアップを取る。
- 別名が既存設定と重複する場合は別の名前を求める。
- 管理対象外の既存 Host 設定は変更しない。専用設定を読み込む Include 行の追加だけを、差分表示と明示的な確認後に許可する。
- Include 行の追加前にはバックアップを作り、同じ読み込み行を重複追加しない。
- Include 行の追加を断った場合は、手動で追加できる内容を表示する。
- 取り込んだ既存鍵は元の場所に置き、ファイルパスだけを記録する。

## JSON の管理情報

- version に JSON 形式のバージョンを保存する。
- keys に鍵の固定 ID、管理名、指紋、ファイルパス、作成・取り込みの記録を保存する。
- hosts に接続先の固定 ID、別名、アドレス、ユーザー名、ポート、OS を保存する。
- registrations に鍵 ID と接続先 ID の対応、登録・解除の記録、最後の確認結果を保存する。
- 鍵名と接続先の別名を変更しても、固定 ID により登録履歴との対応を維持する。
- 登録状態（登録済み・解除済み・結果不明）、接続確認（成功・失敗・未確認）、処理の進捗を分けて記録する。
- 管理対象外として発見しただけの鍵・設定を自動で取り込まない。

## 管理対象外の鍵と設定

- 操作・取り込みの記録がない鍵と設定は、一覧に管理対象外と注記する。
- 注記は画面表示とし、元のファイルにコメントを書き込まない。
- 管理対象外は変更、移動、削除しない。明示的な取り込み後に管理対象とする。
- 記録と実際の状態が一致しなければ要確認と表示し、変更処理を止める。

## 既存の鍵と設定の探索範囲

- ~/.ssh/ 内の鍵候補と、ツール専用ディレクトリ内の鍵を探索する。
- ~/.ssh/config と、そこから読み込まれる接続設定を探索する。
- ユーザーが明示的に指定した鍵ファイルも対象にする。
- PC 全体の検索と、ネットワーク上の端末の自動探索は初版に含めない。
- 発見した鍵・設定は、管理記録がなければ管理対象外として注記し、明示的な取り込みまで変更しない。

## 既存鍵の取り込み

- 秘密鍵ファイルを選択した場合は、対応する公開鍵を確認し、鍵の組として管理する。
- 公開鍵ファイルを選択した場合は、対応する秘密鍵の場所も指定できるようにする。
- 公開鍵のみの取り込みも許可し、公開鍵の登録・解除を管理する。
- 利用可能な秘密鍵を確認できなければ、接続確認は未確認として記録する。
- 取り込み前にファイルの場所、公開鍵の指紋、管理名を表示して確認する。
- 取り込み元のファイルは元の場所に残す。
- 取り込み自体では接続先への公開鍵登録を行わず、別の操作として実行する。

## 登録解除と削除

- 公開鍵の登録解除と、ローカルの鍵ファイルの削除は別の操作にする。
- 管理記録だけを外す独立操作は初版から省く。
- 記録された登録先が残る間はローカル鍵の削除を止める。
- 接続できない登録先があれば手動解除の手順を表示し、鍵ファイルを残す。
- ツールが把握している登録先に限ることを、削除前に表示する。
- 自動解除の前に接続先、ユーザー名、解除する公開鍵の指紋を表示する。
- 別の鍵またはパスワードによる新規接続を確認できた場合だけ、ユーザーの最終確認後に自動解除する。
- 現在の接続が維持されているだけでは、別の認証方法を確認できたことにしない。
- 別の認証方法を確認できない場合は自動解除を止め、手動手順を表示する。

## 接続失敗時の案内

- 到達できない場合は、アドレス、ポート、ネットワーク、SSH サーバーの起動を確認する手順を案内する。
- 認証できない場合は、別の鍵やパスワードでの再試行、または公開鍵の手動登録手順を案内する。
- 接続できたが登録できない場合は、登録先の権限と設定を確認する手順を案内する。
- 原因を判定できない場合は、エラー内容と確認項目を表示し、断定せずに止める。
- 手動手順の作成時に接続先 OS が未確認なら、Windows、Linux、macOS からユーザーが選択する。
- OS を推測して登録コマンドを実行しない。

## 失敗と再実行

- 完了した段階を JSON に記録し、再実行時は実際の状態を確認して続きから進める。
- 作成済みの鍵は失敗時にも残し、再利用する。
- 登録済みの公開鍵は重複追加しない。
- 登録後の接続確認失敗は、登録済み・接続未確認として表示する。
- 通信断で成否が不明なら結果不明として記録し、再接続して確認する。
- 管理対象の公開鍵が解除先に既になければ解除済みとして記録する。
- 失敗を理由に鍵ファイルを自動削除しない。

## インストール・更新・アンインストール

- 本体はユーザー専用の場所に配置し、管理者権限を求めない構成にする。
- 同じインストールスクリプトの再実行で本体を更新し、鍵・JSON・接続設定は保持する。
- 自動更新は初版に含めない。
- アンインストールでは本体とインストーラーが追加した PATH 設定だけを削除する。
- アンインストール時も鍵・JSON・接続設定を残し、接続先の公開鍵を解除しない。

## 配布対象

- 実行元は Windows、Linux、macOS の3 OS を対象とする。
- 各 OS の x64 と ARM64 向けに、合計6種類のバイナリを配布する。
- インストーラーが実行元の OS と CPU を判定し、対応バイナリを取得する。
- 対象外の環境では理由を表示して終了する。

## 確定した実装方針

- 本体は Go とし、既存の ssh / ssh-keygen を呼び出す。
- インストーラーは既定で最新の正式リリースを取得し、特定バージョンも指定可能にする。
- JSON は一時ファイルに完全に書き込んだ後に置き換え、直前の正常な内容をバックアップする。
- 管理データを変更する処理の同時実行は許可せず、理由を表示して後から再実行するよう案内する。
