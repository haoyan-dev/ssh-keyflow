# SSH KeyFlow

Status: ready-for-human
Released: v0.1.0（`ee3a00f`）。自動登録・解除はv0.5.0（`6a09684`、PR #8、ADR 0001）で廃止

## Problem Statement

VPS、Tailscale内の端末、ノートPC、メインPCで、自分のSSH鍵と公開鍵登録を安全に管理したい。Windows、Linux、macOSごとの手作業と、登録履歴の不明瞭さを減らしたい。

## Solution

Go製CLI SSH KeyFlow（コマンド名 ssh-keyflow）をバイナリ配布する。対話メニューから環境確認、鍵作成・取り込み、接続先管理、公開鍵登録・解除、ローカル鍵削除を行う。操作記録のない鍵や設定は表示と注記だけにとどめる。

## Implementation Decisions

- SSHと鍵生成にはOSのOpenSSHコマンドを利用する。認証プロトコルは実装しない。
- アプリケーション、永続状態、外部SSH操作を小さな責務に分ける。
- JSONのversion、keys、hosts、registrationsと固定IDを用い、登録状態・接続確認・操作進捗を分ける。
- 意図と進捗を変更前に永続化し、結果不明は実状態を確認して再開する。
- 一時ファイル置換と直前の正常バックアップ、変更の排他を使う。破損状態や未対応versionを空で上書きしない。
- 鍵や設定の発見と明示的な取り込みを区別する。ファイル不一致では変更を止める。
- 秘密値はOpenSSHの端末対話に任せる。自動解除には対象鍵や多重化接続を使わない別認証の新規ログインと最終承認を要求する。
- 接続先OSと標準の公開鍵登録先を確認してから変更する。Windows管理者用登録先の共有範囲を表示する。
- 管理対象設定はJSONから生成する。既存設定へのInclude追加には差分・バックアップ・承認を要求する。
- GitHub Releasesの6種類のバイナリをインストールスクリプトで配布する。配布元は実際のリポジトリを明示して指定し、架空の公開済みリリースを前提にしない。

## Testing Decisions

- 前回提示したCLI境界とインストーラー境界を使用する。今回の最後まで実装する指示に従い、この範囲で進める。
- CLIの公開操作を、一時ディレクトリと外部コマンド実行の代替応答を使って検証する。実際のユーザーのSSHファイルや未指定の実機を変更しない。
- インストール・更新・アンインストールはテスト用の配布物と配置先で検証する。実際の公開リリース取得と区別する。
- 1つの振る舞いを失敗テスト、最小実装、成功確認の順で追加する。内部構造を模倣するテストを避ける。
- 既存テストはない。6対象クロスビルドとOS固有の実機検証を区別して報告する。

## Out of Scope

- 他人の鍵管理、Tailscale SSH固有の認証・ポリシー変更、ネットワーク端末探索、全ディスク探索。
- 自動更新、自動権限昇格、管理記録だけを忘れる操作、認証情報の保存。
- 未承認の実機変更とリリース公開。エージェント用の非対話・JSONコマンド追加案は別途検討とする。
